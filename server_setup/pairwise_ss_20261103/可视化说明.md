# 第20轮可视化

## 文件与目的

- `visualize_midpoint.py`：加载旧基线和SS第20轮验证后权重，生成连续跟踪视频、六帧拼图和SS矩阵诊断。复用现有Tracker，严格加载参数，不修改训练源文件或权重。
- `make_visual_gallery.py`：将完整输出整理为可离线打开的中文 `index.html`。
- `progress.py`：本轮修复IoU误匹配Loss/giou，已运行的面板需要退出面板程序后重新启动，训练tmux会话1无需操作。

## 解释边界

两组均为第20轮；固定seed20261104在排序后的LasHeR测试目录中抽取3个序列，各运行前300帧（不足则到结尾）。首帧真实框初始化，之后连续使用各自预测，不能把这900帧当作245序列的正式评测。

关键帧在推理前均匀确定，不根据结果筛选。绿色真实框、蓝色基线、红色SS；右侧热红外仅展示原图，不把可见光坐标的预测框直接画上去。视频回放20FPS不是实际推理速度。

SS诊断使用首帧模板和同一当前帧GT中心搜索裁剪，在block输入索引3/5/7/9/11提取两路特征。模板前64tokens，搜索后256tokens，两路分别构建余弦相似矩阵。两组的搜索裁剪完全相同，这一诊断不使用各自跟踪裁剪，也不会重置连续跟踪状态。不能把诊断当成真实跟踪输入的效果图。

热力图相似度固定[-1,1]、绝对差异固定[0,2]。原矩阵保存NPZ，统计保存JSON，包含跨模态矩阵MSE、各模态非对角均值与标准差。结构差异减小不代表定位必然提高，需结合轨迹观察；非对角统计只是排查特征过度相似的线索。

## 来源与保留

manifest.json记录权重与配置路径/SHA、脚本SHA、序列选择、轮次。每序列frames.json记录所展示帧号、实际处理帧数、完整序列帧数和GT SHA。基线/SS预测文件不覆盖历史评测。输出目录存在则拒绝运行，失败重试须用新目录。

当前脚本仅接受epoch20，原因是该轮完成验证、保存的LoRA权重已合并，与现有RGB-T Tracker加载约定一致；禁止仅修改文件名就拿非验证轮次套用。

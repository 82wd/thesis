# SEATrack 三个想法：已经做了什么，还需要做什么

整理日期：2026 年 11 月 17 日。

本文依据当前本地代码、配置、实验日记、实验日志和已归档结果整理。本次没有实时登录服务器查询，因此“已经启动”“最近轮次”均是有时间戳的历史记录，不代表此刻仍处于该状态。未找到最终报告的项目统一写为“待核验”，不推断已经完成或尚未开始。

## 一、先把三个想法的关系讲清楚

你现在不是三个互不相关的新模型，而是两条研究路线、三个工作包：

| 想法 | 要回答的问题 | 当前阶段 |
|---|---|---|
| 1：SS 表征约束（10.18） | 让两种模态的空间关系更一致，能否提高跟踪性能？ | 初版实现、训练、五个 benchmark 评测均已完成；结果不支持全面提升 |
| 2：频段融合（11.9） | 不直接相加，改为跨模态低／高频组合，是否更有效？ | 历史观察已做；当前非学习特征层模块、四组配置和单测已完成；真实权重闭环及全量验证缺少完成证据 |
| 3：SS 小步消融（11.12） | SS 为什么不稳定？只约束 search、只约束某层，会怎样？ | template-only / target-aware 已出结果；search-only 多层已启动过；五个单层配置与曲线记录已实现，最终结果待补 |

**你当前最重要的工作是补齐对照与最终评测，不是再同时增加几个新模块。** 优先收尾 SS 小步消融，同时做频段融合的固定权重评测。先分别回答是否有效，再考虑组合。

## 二、想法一：SS 已经完成到哪一步

### 已经完成

1. **实现了完整 patch 两两关系的 SS。** 模板与搜索分别计算；每个 patch 沿通道归一化，得到区域内相似度矩阵，再对齐两模态矩阵的 MSE。没有新增可学习参数。
2. **接入训练目标。** 在零基 block 索引 3、5、7、9、11 的入口取特征。每层为 `0.5 × 模板 SS + 0.5 × 搜索 SS`，所选层取均值，再乘 0.1 加入跟踪损失。普通推理不计算该辅助损失。
3. **完成三类模态训练和五项评测。** RGB-T 60 轮、RGB-E 45 轮、RGB-D 25 轮；结果如下。
4. **做过中期关系图与失败分析。** 第 20 轮完成 3 条序列、750 帧可视化；60 组配对诊断中 58 组跨模态 SS MSE 更低。另有逐序列差异、关键帧回放、交换上一帧搜索框等分析。

| 数据集 | 指标 | 历史基线 | 初版 SS | 变化 |
|---|---|---:|---:|---:|
| LasHeR | SR | 57.51% | 56.71% | −0.80 个百分点 |
| RGBT234 | MSR | 63.73% | 64.67% | +0.94 个百分点 |
| VisEvent | SR | 60.26% | 59.63% | −0.63 个百分点 |
| DepthTrack | F 分数 | 63.23% | 60.97% | −2.26 个百分点 |
| VOT2022-RGBD | EAO | 0.73760 | 0.72659 | −0.01101 |

解释边界：这些是历史同评测协议下的结果；RGB-D / RGB-E 基线权重来源仍有追溯问题。关系矩阵更一致不等于跟踪更准，案例回放也尚未证明“SS 是跟偏的直接原因”。已有按序列重采样的不确定性分析，但它没有覆盖训练随机种子差异。

### 还没有完成或尚未验证

- **最初提到的平均池化 anchor / 可学习 query token，并未在当前 SS 中实现。** 当前代码是全 pairwise SS。它们是可选后续设计，不是初版欠缺的必补步骤。
- 尚未得到跨数据集稳定提升的结论；单次训练也不能证明收益稳定。
- 0%、10%、20%、30% 搜索框偏移的系统敏感性实验，在日记中仍是计划；不能把它当作已完成证据。

### 下一步怎么安排

不建议现在把同样的全 pairwise SS 再铺到更多数据集。先完成想法三，确定问题更接近区域选择、层位置，还是约束强度。若这些简单消融仍无稳定收益，再决定是否改成 anchor-based SS，或停止把 SS 作为主创新点。

**这一方向的当前结论可以写：** 初版 SS 能促进所测空间关系的一致性，但未获得全面跟踪收益，因此进一步做区域、层位置与强度消融。

## 三、想法二：频段融合已经完成到哪一步

### 已经完成的历史探索

- 做过固定搜索区域的频段互换回放：8 段片段、88 帧、880 次预测。
- 在第一版 SS 权重上，白车失败帧采用“红外低频 + RGB 高频”，IoU 从 0 提高到 0.811；匹配 RMS 后为 0.825。人脸失败帧没有被救回。
- 六段稳定对照的平均 IoU 从 0.802 降至 0.768 / 0.771。因此没有证据支持固定的模态频段分工普遍成立。
- 还做过**另一条历史分支：决策图上的可学习频段融合**。仅拟合两个权重，验证位置分类交叉熵从 2.72052 降至 2.69162；做过两条闭环案例，但整体序列收益很小。旧记录提到启动后续全量评测，当前核对材料没有对应最终报告，需单独查收。

上述历史试验与当前“无 SS、非学习、特征层频段融合”不是同一个实验。不能把它们的结果混写为当前模块已经完成的全量验证。

### 当前代码已经完成

- 在最后一层归一化、恢复空间顺序后的 search 特征上，替换原 `RGB + X`。
- 实现二维实数 FFT、径向低高频分割、复数频谱加权、逆 FFT；默认 cutoff = 0.25。
- 保留完整复数系数；无新增可学习参数，梯度仍能回传。
- 实现四组配置，全部关闭 SS：

| 配置 | 内容 |
|---|---|
| `rgbt_freq_baseline` | 原始相加 |
| `rgbt_freq_equal` | 低／高频 RGB 权重均为 0.5，gain = 2；代码直接返回原相加 |
| `rgbt_freq_rgb_low` | RGB 低频 + 红外高频，gain = 2 |
| `rgbt_freq_ir_low` | 红外低频 + RGB 高频，gain = 2 |

- 已有显式 checkpoint 加载和评测配置隔离。
- 11 月 16 日 CPU 环境中全部 15 项测试通过：6 项频段测试、9 项原 SS 测试。包含等权一致性、合成频率信号、网格形状、梯度和配置检查。

### 还要做的必需步骤（按顺序）

1. **确认权重来源。** 四组使用同一份确实未经过 SS 训练的 RGB-T 权重，保存文件哈希、epoch 和配置。关闭 SS 开关不能消除权重已经学到的 SS 影响。
2. **做真实权重 GPU 短测。** 验证加载、有限输出、正常轨迹与实际评测入口。此前单测的 checkpoint 兼容检查使用构造的同结构 state_dict，不等于真实服务器权重已验证。
3. **验证 baseline / equal 的完整轨迹一致性。** 先用短序列排错，再核对正式评测轨迹；若不一致，先排查配置、权重和评测流程，不解释频段收益。
4. **固定权重评测两个频段选择组。** 先在验证集检查合理性，再按统一测试协议计分。每组保留独立轨迹、指标和逐序列差异，不能只挑救回的帧。
5. **拆开频段选择与幅值影响。** gain = 2 不保证融合后 RMS 与原相加相同。预先确定 gain / RMS 对照方案，在验证集分析，避免根据测试集挑有利参数。
6. **记录额外推理成本。** 在相同设备和计时口径下记录延迟或 FPS；无参数不代表没有计算开销。

建议先以 LasHeR 为主要判断集；若得到稳定、可解释的收益，再用 RGBT234 检查泛化。需要完整比较时，四组必须使用相同名单与计分协议。

**现在不必先做：** 可学习频段权重、重新训练全部变体、SS + 频段联合训练、大范围 cutoff 网格搜索。先证明现有即插即用模块有没有价值。

## 四、想法三：SS 补救已经做了哪些，还欠哪些

### 已经完成：两种历史区域调整

| 方案 | 改动 | LasHeR SR | RGBT234 MSR | 状态 |
|---|---|---:|---:|---|
| 未加 SS | 无辅助约束 | 57.51% | 63.73% | 已有基线 |
| 初版 SS | 模板 + 搜索，完整 pairwise | 56.71% | 64.67% | 已完成 |
| A：template-only | 只保留模板 SS | 57.31% | 64.03% | 60 轮及两集全量评测完成 |
| B：target-aware | 保留模板；搜索约束前景相关位置对 | 57.29% | 64.06% | 60 轮及两集全量评测完成 |

A/B 恢复了部分 LasHeR 表现，但仍略低于未加 SS；同时损失了部分 RGBT234 收益。因此只能说“部分恢复”，不能说补救已经成功，也不能确定背景关系就是退化原因。

### 已实现、已启动过，但最终结果需要查收

**半权重对照：** 模板与搜索都保留 0.5，SS 总权重改为 0.05。11 月 16 日日记最近核验到 25/60 轮；该轮次不是当前状态。需要查收末轮权重和同协议评测报告，才能区分 A 的改善来自“删除搜索约束”还是“总约束减弱”。

**Search-only 多层：** `rgbt_ss_search`，模板权重 0，搜索权重 0.5，总权重 0.1，所以附加目标为：

`L_total = L_tracking + 0.05 × mean(所选层的搜索 SS MSE)`

已实现关闭区域跳过计算、每层损失输出、训练／验证日志与 TensorBoard 曲线。服务器 9 项既有测试通过，真实数据两轮短测及 checkpoint 重载通过。正式训练曾在首轮后停滞，修复后重新从原初始化开始；11 月 17 日 01:45 的最近记录为第 1/60 轮 950/1875 批，确认实际训练已推进。**尚无本次核对到的 60 轮完成与最终精度证据。**

### 已准备配置，但没有查到正式完成证据

五个单层配置：`rgbt_ss_search_l3`、`l5`、`l7`、`l9`、`l11`。层号为零基 block 输入位置。已有配置和日志接口，不等于五组已经训练。现有记录明确没有批量启动全部单层实验。

### 最需要注意：当前新旧训练预算不相同

| 项目 | 历史 A/B 等实训记录 | 当前 search-only 配置 |
|---|---:|---:|
| 有效 batch | 4 × 累积 16 = 64 | 32 |
| 每轮采样 | 59,968 | 60,000 |
| 每轮优化器更新 | 937 | 1,875 |
| 60 轮更新总数 | 56,220 | 112,500 |

当前 search-only 的更新次数约为历史方案的两倍。即使都训练 60 轮，也不能直接将性能变化归因于“只约束 search”。

建议保留已经进行的训练作为探索结果；先检查是否已有与当前预算匹配的无 SS、原版 SS 对照。若没有，再补相同预算的必要对照，或将后续整组消融统一到明确的另一套协议。不要为了省一次对照而把预算差异藏起来，也不必未经核验就重跑全部历史实验。

### 下一步具体顺序

1. **查收半权重和 search-only 多层的当前结果。** 区分正常训练、已结束、异常停止；完成必须有末轮可加载权重与相应评测报告，不能只看轮数或文件存在。
2. **确定统一对照协议。** 将初始化、seed、有效 batch、采样量、更新次数和评测名单逐项列出；为 search-only 找到或补齐匹配的无 SS／原 SS 对照。
3. **完成 search-only 多层评测。** 先看 LasHeR，结合逐序列变化判断，而不是只比较训练 loss。
4. **按同一协议完成五个单层实验。** 每组从同一初始权重独立训练；不要在上一组训练结果上继续训练。最终得到“无 SS、原 SS、search-only 多层、五个单层”的清晰对照。
5. **导出曲线。** 每层 train / val SS、加权 SS、跟踪损失和相应跟踪指标；关闭区域日志中的 0 表示没计算，不代表已经对齐。
6. **只对有希望的候选做重复种子。** 建议用包括初次运行在内的 3 个种子，与同种子基线成对比较，报告均值与波动。此项是稳定性验证建议，目前未完成。
7. **通过小范围验证后再扩展 benchmark。** 如果简单消融仍没有稳定收益，就明确记录负结果，再决定是否换 SS 表达方式。

## 五、接下来你最该推进的任务清单

以下为建议执行顺序，不表示已自动启动这些实验。

| 优先级 | 任务 | 完成后必须留下什么 |
|---|---|---|
| P0 | 查收半权重、search-only 多层及历史频域评测状态 | 有时间戳的状态、末轮权重身份、已有报告或明确缺项 |
| P0 | 整理 SS 新旧训练预算，确定公平对照 | 一张初始化／batch／样本数／更新次数／seed 表 |
| P1 | 当前频段模块真实权重短测、baseline/equal 一致性 | 真实权重哈希、检查记录、轨迹差异报告 |
| P1 | Search-only 多层完成训练与统一评测 | 完整指标、逐序列差异、train/val 曲线 |
| P1 | 半权重对照收尾 | 与初版及 template-only 的同协议比较 |
| P2 | 两种固定频段组合与幅值对照 | 正负案例、完整指标、延迟、幅值敏感性结果 |
| P2 | 五个 search-only 单层消融 | 每层配置、权重、指标和曲线汇总 |
| P3 | 候选重复种子与跨集检查 | 均值、波动、可复核的成对基线 |
| 条件性后续 | Anchor SS、可学习频段或两路线组合 | 只有前述证据支持继续时再设计 |

可以并行的是：**SS 训练收尾／消融，与频段固定权重评测。** 研究上两者独立；现阶段频段方向不需要为了跑评测而先重新训练四个模型。
